The root Prism project defines capacity decisions and pilot selection. Build and verify the checkout with Prism Code 0.11.0. The model carries 44 theorems and 64 executable acceptance vectors. The project verifier checks the built holo against the model on disk and replays its vectors. The artifact reports evidence level P0. Its project verification covers identity and replay. ## Configured capacity and sparse scaling in 0.5.0

For a configured virtual machine, let P be the platform ceiling in whole MiB, G the guest ceiling bounded by the QEMU process address-space limit, and B the backing byte budget. B includes available filesystem bytes, the process file-size limit and the signed file-offset limit. The policy computes

```text
D = floor(max(0, B − 4096) / 1048576)
C = min(P, G, D)
```

The 4096 bytes preserve the previous literal until its replacement commits. For every natural-number triple P, G, D, the Prism module proves that C satisfies each limit, dominates every other feasible size, and is monotonic in D. When the target min(P,G) fits D, C reaches that target. The installed executable calls the Rust export of the same policy. Replacing the selection of the smaller input with the larger input makes `prism-code check .` reject VR-15 at `CapacityPolicy.admissible`. Restoring it passes the kernel check and vector replay. The launcher also compares the result against the original configured target so a low process limit cannot silently reduce a max request.

These claims concern the supplied bounds. Firmware describes installed-system capabilities, the domain describes a guest configuration, and the backing budget is observed before reservation. QEMU startup, Linux onlining, metadata allocation, memory pressure and failure recovery are systems behaviors. The integration test boots at the computed size with a reserved DIMM and checks ordinary guest accesses after onlining. End-to-end latency depends on the working set, the kernel page cache and the backing device.

The ordered directory has one key per live 64 MiB leaf. An empty extent has constant directory space and initialization work in the advertised capacity. A page lookup costs O(log(L+1)) for L live leaves. Discarding a range seeks to its first live leaf and visits only its K live leaves, with O((K+1) log(L+1)) directory work plus destruction of the affected entries. At most two partial leaves require boundary mask updates. Literal index maintenance is additional. Logical store charge includes live keys, pointers and leaf payloads. RSS also includes tree-node slack and the allocator.

The sparse regression program sets a 64 MiB process address-space limit, writes eight distinct dense pages across leaf boundaries and at both ends of the range, and checks all bytes before and after partial and full discard. Its file-backed variant creates a sparse test file. The packaged VM launcher uses full preallocation. To reproduce after building the host:

## Dense slot reclamation in 0.5.1

The previous file-backed arena pushed retired slot numbers onto a growable vector. The new arena maintains one availability word per 64 slots reached and links words with available lanes. Both slot selection and return take constant time once the word exists. Growing the word vector on admission has amortized constant cost. The arena uses the existing Prism word-membership and empty-group exports. It commits ownership under its lock only after a complete page write. A final partial word exposes only slots that fit the reserved file.

The release path for a literal slot only updates existing metadata or releases the entire ledger when the last owner drops. This property applies to the slot allocator. The page directory and literal index have their own resource costs. The ledger retains its word capacity until the arena drains, and a completely full arena now pays a small metadata cost before any pages are retired.

## Ownership-aware admission in 0.5.2

All successful page replacements apply the existing Prism index-size decision when they retire the last strong owner of a dense base. The directory write lock protects this decision. A successor holding the same base already has its own reference before replacement. The index rebuild remains fallible and the previous index stays usable if memory is tight.

An overwrite may additionally nominate its incumbent's immutable base when another logical owner will retain that base. The candidate passes the same exact reconstruction, edit limit and representation-cost gates as an indexed candidate. A residual nominates its original literal directly. Candidates found by both routes are read once, and an exact indexed match still takes precedence. An exclusive base can match exactly but retaining it solely to store a new residual would add cost.

## Concurrent memory-file requests

The memory server can receive requests concurrently. Each partial-page patch decodes, merges and commits while holding the directory write lock. Whole-page writes use the same commit path. This preserves the single replacement-slot bound. Full-page reads in one FUSE request share a directory read lock and clear contiguous missing groups in one operation. Timestamp updates and the server's traffic counters are synchronized separately.

The regression test starts four writers on disjoint byte ranges of each page. A planted implementation that released the read lock before committing the patch lost byte 32 on page 0. The corrected implementation passes that test, validates range ends across occupied and empty groups, and retains an existing dense page after a failed partial write to a sealed backing file.

## Parallel representation fitting

A full-page writer that encounters contention can snapshot the incumbent selector and the shape and credits of its 64-page Verdant policy group. When readers hold the directory it can fit the leading page after a shared snapshot. When another writer is queued, the current writer can release the lock during a fit anywhere in its batch. At most one prepared candidate per calling worker is held. Uniform pages, potential live literal matches and pages already scheduled for direct literal capture skip preparation. Exact dictionary admission and backing writes still happen under the exclusive lock. The writer accepts a prepared result after comparing both model inputs, or fits against the current inputs once while holding the lock. Partial-page updates still decode, merge and commit in one critical section.

A public-ABI test holds a reader open while a writer finishes fitting, then verifies its commit and exact bytes. Deterministic interleavings independently change the incumbent selector, update the region from a neighboring page, and publish an exact duplicate from another group. ## Latency and throughput bounds

vTensor's VT-12 matrix model describes a transfer and computation schedule and checks execution against GGML's CPU oracle. VR-22 applies that approach to two schedules for the same verified vRAM page work. Its time variables are nonnegative ticks measured on one clock. The proofs apply across hosts. The values of the time variables depend on the host, workload and concurrent load. [vTensor schedule](https://github.com/afflom/vTensor/blob/b0ce3f6b72ce3b12ea3081977b61cbb01b36980f/app/src/MatrixExecution.lex.tex) · [Prism model](../app/src/Performance.lex.tex)

- **Equal-work throughput.** In a serialized schedule, two segments of duration O consume 2O elapsed ticks. If those segments overlap completely and the remaining critical path is unchanged, the new schedule saves O ticks and incurs H extra critical-path ticks. For fixed useful bytes, throughput increases exactly when H < O. For a fit of F ticks and independent work of B ticks, ideal overlap is min(F, B). The best possible time in that two-task model is max(F, B) + H. A failed speculative fit can increase H. The runtime's cumulative lock waits sum overlapping worker intervals, so subtracting those totals does not measure O.
- **One page's latency.** With common service time S, old wait Q₀ and new wait Q₁, the page improves exactly when Q₁ + H_page < Q₀. Here H_page is the additional work on this page’s own path. A batch can finish earlier while its leading page finishes later.
- **A p99 deadline.** For N samples and nearest-rank p99, a deadline D is met exactly when at most floor(N/100) samples exceed D. With paired page observations at D, the new miss count is the count late in both schedules plus the newly late count. Misses do not increase precisely when newly late pages number at most the rescued pages. This counting identity by itself provides no probability guarantee for the next run.
- **Best measured feasible time.** Starting with a feasible incumbent, the model takes a shorter candidate time only when the candidate meets the deadline. The result is attainable and no greater than the time of either eligible input. Repeated application therefore minimizes elapsed time over any finite set of measured, eligible plans. Equal byte counts make this equivalent to maximizing measured throughput. The search domain in the guest report is the tested VM widths.

The guest records each worker's sum of timed page-write intervals after readback, before sorting the samples. Each worker executes its writes sequentially within the common timed window. For B total useful bytes, elapsed time T and longest worker sum L, T ≥ L and B/T ≤ B/L. The latter is a ceiling conditional on the observed intervals. Changing the host or scheduling policy can change L. The receipt also checks that the reported p99 occupies its required rank, including ties. Measurements cover guest first-touch writes, including stalls during those writes. Backend callback counters span the entire VM lifetime.

The CI artifact includes `parallel-guest.json` and `performance-frontier.json`. For each vRAM width the report uses the largest per-trial p99 and total verified bytes divided by the sum of write times across four runs. It evaluates the registered Prism selector at every observed deadline where eligibility changes. Each entry applies up to the next entry and budgets below the first have no qualifying width. The choice applies to VM vCPU count for this workload. The report can be reproduced with the locked automation dependencies installed:

```sh
node automation/performance.mjs parallel-guest.json performance-frontier.json
```

Two vCPUs had a higher worst-trial p99 at 172.096 µs and lower aggregate throughput at 253.7 MiB/s. Eight vCPUs reached 3,194.672 µs and 172.3 MiB/s. A different run can change every breakpoint. ## Tail ranks and parallel workers

VR-24 proves four additional timing properties in the [Prism performance model](../app/src/Performance.lex.tex).

- For N observed page latencies, the nearest-rank p99 occupies position N − floor(N/100) in ascending order. If B observations are strictly below a proposed p99, E equal it and A are above, the rank falls in the tied block exactly when A ≤ floor(N/100) < A + E. This rejects an empty population. For a deadline applied to a nonempty workload, p99 meets the deadline exactly when at most floor(N/100) observations exceed it.
- Let L be the total measured page-write time in one sequential worker, M the longest such total for the remaining workers (zero for one worker) and H the time outside the longest total in the common elapsed window. The window is max(L, M) + H, so both worker totals bound it from below. If only L shortens by S, with M and H fixed, the exact window reduction is min(S, max(0, L − M)). A tied longest worker has zero individual leverage under those assumptions. A shared backend improvement can shorten several workers or change H.
- For new guest receipts the frontier evaluator checks each vRAM trial's rank witness and replays the single-worker gain bound through Prism. The report includes the two longest worker totals, time outside the longest total, and the bound for that trial. Older receipts without worker and rank observations still produce a frontier and explicitly report the missing evidence. A receipt declaring timing evidence must supply it at every tested width.

Changing the strict rank boundary to allow equality and replacing the minimum gain by the maximum caused Lean to reject `rankWitness` and `laneGain`. Restoring the definitions passed the proof and acceptance-vector gates.

VR-27 proves that an already eligible candidate makes the same timing decision at every looser deadline, and considering a dominated plan after its dominator leaves the selected time unchanged. The evaluator now sorts widths by their measured tail once, visits each new width once, and publishes after every width tied at the same deadline has been considered. With W widths the sort costs O(W log W) comparisons and selection uses W − 1 Prism dispatches. The previous sweep could dispatch W times per distinct deadline. Restricting eligibility to exact deadline equality caused Lean to reject both new theorems. The restored model passes 40 theorem checks and 52 acceptance vectors.

### Native Prism read windows

vRAM 0.6.6 links the Rust export of `ReadPolicy::window` into the Linux block server. For an admitted read, the Verdant adapter supplies the remaining page count, frame capacity and recovery mode. In ordinary mode the result is the smaller of the two counts. VR-53 proves that the result fits the request and frame, advances whenever both counts are positive, and selects exactly one page in recovery mode. The Holo exposes the same definition via a seven-byte J request. The next four bytes are the remaining pages in big-endian order, followed by the frame capacity and the recovery flag (0 or 1). The response is a five-digit page count. The native export accepts full 32-bit counts from the adapter. [Model](../app/src/ReadPolicy.lex.tex) · [Native proof and binding](../device/proof/read)

The transport provides a reusable 64-page frame. A multi-page window uses one Verdant range read. The first successful frame includes the NBD reply header. Later frames contain only page data. If a range fails, the server retries from that frame's first page in single-page mode through the end of the request. A first-page failure returns EIO. A failure following a successful prefix closes the stream. A 4 KiB direct read continues to use a single store call and one response. These bounds count store calls and response frames. Linux can split the guest request and the socket may take several writes to deliver a frame. [Adapter](../host/vram_host.c) · [Wire tests](../host/tests/nbd_framing.c)

The release comparison issues direct reads at 1, 2, 16, 64, 65 and 128 pages per request against vRAM, its predecessor and zram. Each of three trials reads 128 shuffled starting offsets per size and backend. The workload uses the same 4 MiB mix of patterned and independent pages for all three devices and checks every returned byte outside the timed call. The receipt preserves the run p50 and p99 and the Prism median verdict per size. `node automation/swap-latency.mjs swap-latency.json replay.json --read-windows` requires all six sizes. [Workload](../host/tests/swap_read_windows.py) · [Published timings](https://afflom.github.io/vRAM/downloads/swap-latency.json)

Changing the recovery width from one page to two made `prism-code check .` reject `ReadPolicy.bounded` and `ReadPolicy.singleRecovery`. A stale native source made `python3 device/build.py --verify-only` reject the read policy digest. Removing the retry after a failed range made the C wire test stop at the missing final valid page. Restoring the source passed all three gates. The 129-page success case performs two 64-page range reads and one single-page read.

### Mixed reads from the VM memory reserve

Version 0.6.7 executes `MixedReadPolicy::step` while restoring VM memory. A selector, hole, or other local value occupies a guest page but consumes no file slot. A file-backed literal or residual may share the current slot or advance by one while staying within the same backing extent. A gap, reversal or new file ends the span. The compiled Prism policy and archived Holo use the same definition. A five-byte K request carries a local-page flag, an in-extent flag, the previous slot distance and the proposed slot distance. The single-digit response selects stop (0), local decode (1), or file source (2). [Prism policy](../app/src/MixedReadPolicy.lex.tex) · [Native export](../device/proof/mixed-read)

Verdant reads the compact file span into the beginning of the output and reconstructs logical pages in reverse. Each file source lies at or before its destination, so later writes cannot destroy an unread source. Local pages restore directly into their final destinations. The decoder counts selector restores on successful calls. The release check alternates eight paired 64 MiB mixed trials against v0.6.6. Each trial verifies every page and measures 64-page range readback. The generated selectors and independent literals alternate. The reported read throughput is verified bytes divided by time inside the range calls, including warm filesystem cache. The VM memory reserve and the in-memory NBD swap service have separate latency measurements. [Paired VM store readings](https://afflom.github.io/vRAM/downloads/mixed-file-range.json) · [Linux swap latency](https://afflom.github.io/vRAM/downloads/swap-latency.json)

### Packed kernel directory

Version 0.1.1 stores one unsigned long per logical page on amd64. An inline Fill occupies the low eight bits. A literal frame has a page-aligned address. The Prism-generated lock mask occupies bit eight, leaving the low byte and the frame address recoverable while the slot is locked. The kernel adapter checks word size and mask alignment at build time. Each slot owns its lock. The driver releases it before allocating a literal and rechecks the entry before installing the frame. A zero-initialized word represents a zero page.

VR-63 checks the lock marker and payload ranges and proves that subtracting the marker from a held payload recovers that payload.
